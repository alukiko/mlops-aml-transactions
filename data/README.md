# Data

В этой папке лежат два CSV-файла с банковскими транзакциями для задачи детекции отмывания денег. Оба датасета имеют одинаковую структуру и отличаются в первую очередь размером и долей подозрительных операций.

## Задача

Цель работы с этими данными - выявление потенциально незаконных финансовых операций в потоке транзакций. Это типичная задача AML (Anti-Money Laundering), где по характеристикам перевода нужно определить, является ли операция обычной или связанной с возможным отмыванием денег.

В датасете присутствуют как обычные платежи, так и небольшая доля подозрительных транзакций. Благодаря этому данные подходят для задач бинарной классификации, поиска аномалий и анализа сильного дисбаланса классов.

## Откуда этот датасет

Используемые в проекте данные относятся к открытому синтетическому датасету IBM для AML. Он опубликован IBM Research и доступен на Kaggle под названием `IBM Transactions for Anti Money Laundering (AML)`.

Данные являются синтетическими, то есть не содержат реальные банковские операции конкретных клиентов, но при этом смоделированы так, чтобы быть близкими к реальным финансовым потокам. Важное преимущество такого набора в том, что для каждой транзакции известна целевая метка `Is Laundering`, поэтому его удобно использовать для обучения и сравнения моделей.

В открытом источнике можно встретить разные варианты этого набора, включая `HI-Large_Trans.csv` и `LI-Large_Trans.csv`. В этом репозитории лежат версии `HI-Small_Trans.csv` и `LI-Small_Trans.csv`, то есть более компактные варианты того же семейства датасетов.

Ссылки на источник:

- IBM Research: `https://research.ibm.com/publications/realistic-synthetic-financial-transactions-for-anti-money-laundering-models`
- Kaggle: `https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml`

## Какие файлы здесь есть

### `LI-Small_Trans.csv`

- Размер: примерно 620.29 MB
- Количество строк с данными: 6,924,049
- Период транзакций: с `2022/09/01 00:00` по `2022/09/17 15:28`
- Подозрительные операции (`Is Laundering = 1`): 3,565
- Доля положительного класса: примерно 0.0515%

### `HI-Small_Trans.csv`

- Размер: примерно 453.63 MB
- Количество строк с данными: 5,078,345
- Период транзакций: с `2022/09/01 00:00` по `2022/09/18 16:18`
- Подозрительные операции (`Is Laundering = 1`): 5,177
- Доля положительного класса: примерно 0.1019%

На практике `HI-Small_Trans.csv` содержит примерно в 2 раза большую долю положительного класса, чем `LI-Small_Trans.csv`, поэтому эти два файла удобно использовать как сценарии с разным уровнем дисбаланса классов.

Здесь `HI` можно интерпретировать как вариант с более высокой долей подозрительных операций, а `LI` - как вариант с более низкой долей.

## Структура таблиц

Оба CSV-файла содержат следующие колонки:

| Колонка | Что означает |
| --- | --- |
| `Timestamp` | Дата и время транзакции |
| `From Bank` | Код банка-отправителя |
| `Account` | Счет отправителя |
| `To Bank` | Код банка-получателя |
| `Account` | Счет получателя |
| `Amount Received` | Сумма, которую получил получатель |
| `Receiving Currency` | Валюта полученной суммы |
| `Amount Paid` | Сумма, которую списали у отправителя |
| `Payment Currency` | Валюта списания |
| `Payment Format` | Канал или формат платежа |
| `Is Laundering` | Целевая метка: `1` - подозрительная операция, `0` - обычная операция |

## Важное замечание

В исходной схеме CSV есть две колонки с одинаковым названием `Account`. По смыслу это:

- первая `Account` - счет отправителя
- вторая `Account` - счет получателя

При загрузке в `pandas` или другой инструмент их лучше сразу переименовать, например в `from_account` и `to_account`, чтобы не путаться дальше в коде и анализе.

## Какие значения встречаются в данных

- Валюты: `Australian Dollar`, `Bitcoin`, `Brazil Real`, `Canadian Dollar`, `Euro`, `Mexican Peso`, `Ruble`, `Rupee`, `Saudi Riyal`, `Shekel`, `Swiss Franc`, `UK Pound`, `US Dollar`, `Yen`, `Yuan`
- Форматы платежей: `ACH`, `Bitcoin`, `Cash`, `Cheque`, `Credit Card`, `Reinvestment`, `Wire`

## Для чего можно использовать эти данные

- Для бинарной классификации транзакций по признаку `Is Laundering`
- Для анализа сильного дисбаланса классов
- Для feature engineering по времени, банкам, счетам, суммам, валютам и типу платежа
- Для построения baseline-моделей и проверки MLOps-пайплайна
